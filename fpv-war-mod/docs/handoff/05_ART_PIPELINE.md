# Art pipeline handoff

Full technical description: `docs/ART_PIPELINE.md`. This file explains the *why* and what to know before touching art.

## Philosophy
Models are authored **in Python code** (box-UV cubes with integer sizes, procedural textures), saved as `.bbmodel` (Blockbench project), previewed in Blockbench, exported to Bedrock geometry, loaded by GeckoLib.
Reasons: reproducible, reviewable diffs, no GUI needed in the cloud. Tom said "model each one perfectly realistically with animation" and wants Blockbench in the loop; code-generated is fine as long as the result looks hand-made.

## Layout
- `art/lib/artmodel.py` ArtModel (bones, parts, shelf-packed atlas, box-UV face regions, `to_bbmodel`), `art/lib/paint.py` (shaders: solid, camo, metal, weathering, decals), `art/lib/anim.py` (animation writer), `art/lib/pose.py` (FK/IK maths).
- Models: `art/rifleman.py` (+ `rifleman_pose.py` pose solver, `rifleman_anim.py`, `build_rifleman.py`), `art/tank.py` (+ `tank_anim.py`), `art/fpv_drone.py`. Jammer is the old palette model from `tools/blockbench/gen_jammer.py`.
- `art/install.py <name>` copies exported geo (renaming identifier), animation and textures into `src/main/resources/assets/kamikaze_skies/...` and asserts every animated bone exists in the geometry.
- `tools/blockbench/`: `bbmodel.py` writer, `run-blockbench.sh` (headless Electron on Xvfb), `bb-driver.js` (open model, export codecs, screenshots, multi-angle views), `bb-anim.js` (render frames of an animation with Blockbench's own animator), `bb-poses.js`, `bb-probe.js`.

## Conventions (verified against Blockbench; do not "fix" them)
- Authoring rotation: Euler degrees, `R = Rz*Ry*Rx`, +x pitches a hanging limb **forward (-z)**, +x is the entity's right, model front is -z.
- **Bedrock animation files mirror x**: rotation `(-x,-y,z)`, position `(-x,y,z)`; geometry export mirrors pivot x and rotation x,y too. `lib/anim.py` converts when writing keys.
- GeckoLib animations are **additive to the bind pose** (Euler sum). The rifleman's low-ready pose is baked into the model rotations; clips store deltas from it.
- Cubes need integer sizes (box UV). Decals only on north/south/up faces (side-face orientation differs per engine).
- Write animation tracks **complete** (every key) - skipping near-zero keys breaks interpolation and loop seams (a unit test guards loops).
- GeckoLib renderer: `GeoEntityRenderer<E, EntityRenderState>` and override `getDeathMaxRotation` to 0 for living entities with authored death animations; override `getPackedOverlay` to stop the permanent red death tint.

## Rifleman IK
`rifleman_pose.solve(...)` places the right hand on the rifle grip and the left on foregrip/magazine/pouch with two-bone IK each frame, derives rifle rotation from desired forward/up/roll. Add animations by writing a generator `ph -> solve kwargs` in `rifleman_anim.py`'s `SET`.

## Texture/size notes
Rifleman 128x128, tank 256x256 (+ `tank_wreck.png` generated by `wreck()`), drone 128x128. Tank atlas is 255/256 rows used: enlarge before adding parts.

## Looking at results
- Headless: `tools/blockbench/bb-anim.js` renders animation frames (`VIEW=front_r DIST=62 TARGET=0,13,-2`).
- Real game: `KS_DEMO_MODE=soldiers|tank|model|ai`. With a real PC just open Blockbench desktop and drag the `.bbmodel` in.
