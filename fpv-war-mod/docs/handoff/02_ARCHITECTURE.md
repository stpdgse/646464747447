# Architecture and conventions

Package root `com.kamikazeskies` (`src/main/java`). **Rule: logic lives in pure-Java cores with no Minecraft imports; Minecraft glue is thin.** This is what makes the 60+ unit tests possible.

## Packages
| Package | Role | Minecraft-free? |
|---|---|---|
| `sim/` | FlightSim (quaternion rigid body, motors, drag, ground/wall collisions through an interface), Battery (LiPo sag), RadioLink + LinkMonitor + SignalLevel (RSSI model), RateCurve, CameraMath, Vec3d/Quat | yes |
| `input/` | Stick math, keyboard (ramping) and gamepad (SDL3, Mode 2) sources, assist modes (angle, mixed, acro), switch state | yes (SDL poll in `client/SdlGamepad`) |
| `destruction/core/` | BlastSolver (rays through a block field with material strength), SupportSolver (structural support graph), BlastProfile, QualityPreset, material model | yes |
| `destruction/` | BlastExecutor (applies solver to the world, hurts entities, particles, calls `SoldierEntity.alarm`), CollapseManager (budgeted async collapse into falling blocks), LevelField (adapter), MaterialClassifier (block -> material) | no |
| `build/` | DroneBuild (7 tiers + warhead + blackbox, encoded into an int), PartKind, FlightRecorder | yes |
| `ai/` | Role, FearModel, Brain, Behaviour, Marksmanship | yes |
| `mission/` | MissionDef (JSON records), MissionState, MissionRegistry | yes; `MissionManager` and `Outpost` are Minecraft glue |
| `drone/` | DroneEntity (server runs sim; client renders from synced orientation), items, JammerEntity, SoldierEntity (+`SoldierAnim`), TankEntity (+`TankAnim`), Threats, Warhead, TrainingRange, PilotRegistry, DemoMode | no |
| `item/` | PartItem, DroneAssemblyRecipe, DroneWorkbenchBlock, KsComponents (data components), FlightLog | no |
| `net/` | Pilot input payload (client -> server every tick), exit payload | no |
| `client/` | Renderers (GeckoLib), FPV view/camera, OSD, post effects (analog video), key mappings, SDL gamepad | no |
| `core/` | Mod entry, registries (`KsRegistries`), commands, config | no |
| `gametest/` | GameTests per feature (registered in `TEST_FUNCTION`, JSON instances in `data/.../test_instance`) | no |

## Key flows
- **Flying:** client reads input -> `PilotInputPayload` every tick -> `DroneEntity.acceptPilotInput` -> server `serverTick` runs `FlightSim` substeps with battery limits and link effects -> publishes orientation/position -> client `DroneRenderer` + `FpvView` camera ride the drone. Server is authoritative.
- **Impact:** `DroneEntity.serverTick` -> `detonate` (above `detonationSpeed`) -> `BlastExecutor.detonate` -> blast solver -> blocks removed, entities hurt, `SoldierEntity.alarm` -> `CollapseManager.schedule` (support solver finds unsupported blocks, drops them in budgeted batches).
- **Enemy AI:** `SoldierEntity.customServerAiStep`: sense every 4 ticks (`Threats.nearestArmedDrone`) -> `FearModel.tick` -> `Brain.decide` (held 10-60 ticks) -> act (stance, navigation, `shootAt` -> `Marksmanship.hitChance` -> `DroneEntity.shotDown`). Tank: scan -> traverse hull -> cannon.
- **Missions:** `MissionManager.start` force-loads the pad area, `Outpost.build`, spawns tagged enemies (`ks_mission:<id>`), tracks `LivingDeathEvent`, rewards on completion.
- **Animation:** server sets `Stance` (synched byte) / `scanning`; client `AnimationController` maps state via the pure `SoldierAnim.steady` / `TankAnim.hull`; one-shots via `triggerAnim` (`fire`, `flinch`).

## Conventions to keep
- Server-authoritative gameplay. Client only renders and sends input.
- Data-driven where practical (missions JSON, recipes generated by `scripts/gen_assets.py` - do not hand-edit generated recipes).
- Every new system gets (a) a pure-Java core with unit tests, (b) GameTests for the glue, (c) a doc under `docs/`, (d) a `KS_DEMO_MODE` demo if it is visual.
- GameTests: **one solo environment per test** (`test_environment/solo_N.json`, assign an unused N; used so far: 0-7, 20-27, 40-51, 60-73, 80-87, 100-102). Spawn entities with `h.spawn(...)` after `KsGameTests.keepAreaTicking`/`floor`, and wait with `succeedWhen` on entity counters, never fixed delays.
- No real-world insignia, flags or conflict references anywhere (assets, text, briefings).
- Mod resources: namespace `kamikaze_skies`. Entity animation names `animation.<model>.<clip>`; geometry identifier `geometry.kamikaze_skies.<model>`.
- Keep `README.md` status line and the changelog at the bottom of `DESIGN.md` current.
